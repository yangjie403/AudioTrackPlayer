# 录音机功能实现方案：PCM → WAV → 播放与实时波形

本文针对当前项目 `AudioTrackPlayer`，给出一套只使用 Android SDK 的录音实现方案。目标是完成下面的闭环：

```text
麦克风
  ↓ AudioRecord
PCM 16-bit / 44.1 kHz / 单声道
  ├─→ WavFileWriter：追加 PCM 数据，停止时回填 WAV 头
  └─→ 振幅计算：每个音频块得到一个峰值
                    ↓ 切换到主线程
              WaveformView：绘制振幅包络

WAV 文件
  ↓ 解析 fmt/data 块
AudioTrack
  ↓
扬声器或耳机
```

文档中的代码按当前项目的配置编写：

- Kotlin；
- `minSdk 23`，因此使用 `AudioRecord.Builder` 和 `AudioTrack.Builder`；
- 包名 `com.bigjelly.temporun`；
- 不增加第三方依赖；
- 新增一个独立的 `RecorderActivity`，不会破坏当前已有的播放器界面。

## 一、核心原理

### 1. PCM 是什么

PCM（Pulse Code Modulation，脉冲编码调制）是未经压缩的音频采样数据。一次采样由以下参数共同解释：

| 参数 | 本方案 | 含义 |
|---|---:|---|
| 采样率 | 44,100 Hz | 每秒采集 44,100 个采样点，决定时间分辨率和最高可表示频率 |
| 声道数 | 1 | 单声道，录音文件更小，波形绘制更简单 |
| 位深 | 16 bit | 每个采样点占 2 字节，数值范围约为 -32768～32767 |
| 字节序 | little-endian | WAV/PCM 16-bit 的常用字节序 |

PCM 本身没有“文件头”。如果只把 PCM 数组写入文件，播放器无法知道采样率、声道数和数据长度。因此需要在 PCM 外面加一个 WAV 容器头。

### 2. WAV 文件结构

WAV 不是一种独立的音频编码，而是基于 RIFF（Resource Interchange File Format，资源交换文件格式）的容器。WAV 文件由一系列 chunk（数据块）组成，每个 chunk 通常由下面三部分构成：

```text
4 字节：chunk ID，使用 ASCII 表示块类型，例如 RIFF、fmt 、data
4 字节：chunk size，使用 little-endian 表示后续数据区的字节数
N 字节：chunk data，具体数据内容
```

本方案生成的是最常见的“未压缩 PCM WAV”。当音频格式是 PCM、`fmt` 块大小为 16 字节、文件中没有额外 chunk 时，文件头通常是 44 字节，结构如下：

```text
0～11   RIFF 容器头
12～35  fmt  音频格式块
36～43  data 数据块头
44～    PCM 音频数据
```

#### 2.1 经典 44 字节 WAV 头逐字节说明

下面的偏移量是从文件开头开始计算的，偏移量 `0` 表示第一个字节。表中的多字节整数全部使用 little-endian，也就是低位字节在前。例如整数 `0x12345678` 在文件中存储为 `78 56 34 12`。

| 文件偏移 | 字节数 | 字段 | 典型值/计算方式 | 每个字节的含义 |
|---:|---:|---|---|---|
| 0～3 | 4 | `ChunkID` | ASCII `RIFF` | `52 49 46 46`，分别是字符 `R`、`I`、`F`、`F`，表示这是 RIFF 文件 |
| 4～7 | 4 | `ChunkSize` | `36 + dataSize` | RIFF 块大小，不包含偏移 0～3 的 `RIFF` 和本字段自身，共 `fileSize - 8` 字节 |
| 8～11 | 4 | `Format` | ASCII `WAVE` | `57 41 56 45`，表示 RIFF 的具体格式是 WAVE |
| 12～15 | 4 | `Subchunk1ID` | ASCII `fmt ` | `66 6D 74 20`，注意最后一个字节是空格 `0x20`，表示音频格式块 |
| 16～19 | 4 | `Subchunk1Size` | `16` | `fmt ` 数据区大小。未压缩 PCM 的基本格式信息固定为 16 字节，即 `10 00 00 00` |
| 20～21 | 2 | `AudioFormat` | `1` | `01 00` 表示 PCM 无压缩；其他值可能表示压缩编码或扩展格式 |
| 22～23 | 2 | `NumChannels` | `1` 或 `2` | `01 00` 是单声道，`02 00` 是双声道。多声道采样按帧交错存储 |
| 24～27 | 4 | `SampleRate` | `44100` | 每秒采样帧数。例如 44100 的 little-endian 字节为 `44 AC 00 00` |
| 28～31 | 4 | `ByteRate` | `SampleRate × NumChannels × BitsPerSample / 8` | 每秒音频数据占用的字节数；44100 Hz、单声道、16 bit 时为 `88200` |
| 32～33 | 2 | `BlockAlign` | `NumChannels × BitsPerSample / 8` | 一个音频帧占用的字节数；单声道 16 bit 为 2，双声道 16 bit 为 4 |
| 34～35 | 2 | `BitsPerSample` | `16` | 每个声道的一个采样点占多少 bit；16 bit 的 little-endian 表示为 `10 00` |
| 36～39 | 4 | `Subchunk2ID` | ASCII `data` | `64 61 74 61`，表示后面是实际 PCM 数据 |
| 40～43 | 4 | `Subchunk2Size` | `dataSize` | 后续 PCM 数据的字节数；例如 1 秒、44100 Hz、单声道、16 bit 是 88200 |
| 44～文件末尾 | `dataSize` | `AudioData` | PCM 字节 | 按 `BitsPerSample` 和声道数解释的音频采样数据 |

这里的“每字节含义”需要分两种情况理解：

- `RIFF`、`WAVE`、`fmt `、`data` 这类标识是 4 个 ASCII 字节，每个字节对应一个字符；
- 采样率、数据长度、声道数等数值由 2 个或 4 个字节组成，必须按照 little-endian 组合，不能把某一个字节单独当成完整数值。

#### 2.2 一个具体的 44 字节头示例

假设录音参数如下：

```text
采样率       = 44100 Hz
声道数       = 1（单声道）
位深         = 16 bit
PCM 数据长度 = 88200 字节（恰好 1 秒）
文件总长度   = 44 + 88200 = 88244 字节
```

对应的前 44 个字节可以写成下面这样：

```text
偏移 00: 52 49 46 46  AC 58 01 00  57 41 56 45
偏移 0C: 66 6D 74 20  10 00 00 00  01 00 01 00
偏移 18: 44 AC 00 00  88 58 01 00  02 00 10 00
偏移 24: 64 61 74 61  88 58 01 00
```

逐段解释：

```text
52 49 46 46       "RIFF"
AC 58 01 00       0x000158AC = 88236 = 文件总长度 88244 - 8
57 41 56 45       "WAVE"

66 6D 74 20       "fmt "
10 00 00 00       16，fmt 数据区长度
01 00             1，PCM 无压缩
01 00             1，单声道
44 AC 00 00       44100，采样率
88 58 01 00       88200，每秒字节数
02 00             2，每个音频帧 2 字节
10 00             16，每个采样点 16 bit

64 61 74 61       "data"
88 58 01 00       88200，PCM 数据长度
```

PCM 数据从偏移 44 开始。对于本方案的单声道 16-bit PCM：

```text
第 1 个采样点：2 字节，little-endian 有符号整数
第 2 个采样点：2 字节，little-endian 有符号整数
第 3 个采样点：2 字节，little-endian 有符号整数
……
```

例如采样值 `1000` 的十六进制是 `0x03E8`，写入 WAV 时是：

```text
E8 03
```

采样值 `-1000` 的 16-bit 补码是 `0xFC18`，写入 WAV 时是：

```text
18 FC
```

对于双声道，音频帧中的声道通常交错排列：

```text
左声道第 1 个采样点
右声道第 1 个采样点
左声道第 2 个采样点
右声道第 2 个采样点
……
```

因此双声道 16-bit 的 `BlockAlign` 是 `2 × 2 = 4` 字节，每一帧包含左右两个声道的采样点。

#### 2.3 关键字段之间的计算关系

对于 PCM 音频，下面几个字段必须相互匹配：

```text
bytesPerSample = BitsPerSample / 8
BlockAlign     = NumChannels × bytesPerSample
ByteRate       = SampleRate × BlockAlign
dataSize       = sampleFrameCount × BlockAlign
duration       = dataSize / ByteRate
RIFF ChunkSize = 36 + dataSize       // 经典 PCM WAV
fileSize       = 44 + dataSize       // 没有额外 chunk 时
```

以 44100 Hz、单声道、16 bit、录音 3 秒为例：

```text
bytesPerSample = 16 / 8 = 2
BlockAlign     = 1 × 2 = 2
ByteRate       = 44100 × 2 = 88200
sampleFrameCount = 44100 × 3 = 132300
dataSize       = 132300 × 2 = 264600
RIFF ChunkSize = 36 + 264600 = 264636
fileSize       = 44 + 264600 = 264644
```

#### 2.4 为什么有些 WAV 不是 44 字节

44 字节只是“最简单的 PCM WAV”布局，不是所有 WAV 的固定长度。实际文件可能包含：

- `JUNK`：预留空间或填充；
- `LIST`：标题、软件、版权等元数据；
- `fact`：某些非 PCM 编码需要的样本信息；
- 扩展的 `fmt ` 块：例如 WAVE_FORMAT_EXTENSIBLE；
- 其他应用自定义 chunk。

因此健壮的 WAV 解析器不能直接写死“偏移 36 是 `data`，偏移 44 是 PCM”。正确做法是从偏移 12 开始循环读取 chunk：

```text
读取 4 字节 chunk ID
读取 4 字节 little-endian chunkSize
记录 chunk data 的起始位置

如果 ID 是 "fmt "：解析音频参数
如果 ID 是 "data"：记录 PCM 数据位置和长度
否则：跳过这个 chunk

跳到 dataStart + chunkSize
如果 chunkSize 是奇数，再额外跳过 1 字节对齐填充
```

`chunkSize` 表示的是当前 chunk 的数据区长度，不包含 4 字节 ID 和 4 字节 size 字段。RIFF 要求 chunk 按偶数字节对齐，所以跳过未知块时通常需要使用：

```text
nextChunkOffset = dataStart + chunkSize + (chunkSize % 2)
```

#### 2.5 创建和回填 WAV 头的时机

开始录音时还不知道最终的 `dataSize`，所以可以先写入 44 字节占位内容：

```text
偏移 0～43：先写 44 个 0
偏移 44 开始：持续追加 PCM 数据
录音停止：计算真实 dataSize
回到偏移 4：写入 36 + dataSize
回到偏移 40：写入 dataSize
```

其中：

- 偏移 4～7 的 `ChunkSize` 不等于文件总长度，而是文件总长度减去前 8 个字节；
- 偏移 40～43 的 `Subchunk2Size` 只表示 PCM 数据区长度，不包含 44 字节头；
- 如果录音被异常中断，必须尽量执行头回填和文件关闭，否则生成的 WAV 可能无法正确播放。

本项目中的 `WavFileWriter` 使用 `RandomAccessFile` 先写占位头，再通过 `seek(0)` 回到文件开头写入完整头部；具体实现见本文后面的 `WavFileWriter.kt`。

如果停止时不回填这两个长度，很多播放器会认为文件损坏或只能播放很短的一段。

### 3. 为什么录音必须放在工作线程

`AudioRecord.read()` 是阻塞式读取。把它放到主线程会导致界面卡顿，严重时触发 ANR。正确做法是：

1. 主线程创建并启动 `AudioRecord`；
2. 单独的录音线程循环调用 `read()`；
3. 录音线程把 `ShortArray` 写入 WAV，并计算当前音频块的振幅；
4. 只有振幅数值和状态变化切回主线程更新 View；
5. 停止时先让 `read()` 退出，再释放 `AudioRecord`，最后完成 WAV 头回填。

### 4. 振幅包络的计算

对于 16-bit PCM，一个简单且稳定的实时振幅指标是当前音频块的峰值：

```text
peak = max(abs(sample[i]))
amplitude = peak / 32768.0
```

这样可得到 `[0, 1]` 范围的数值：

- `0` 表示这一小段几乎静音；
- `1` 表示接近满量程；
- 每个 20～80 ms 的 PCM 块产生一个振幅值；
- `WaveformView` 将振幅作为距离中线的高度，绘制成上下对称的包络。

峰值适合画波形，因为短暂的爆破音也能被显示出来。若产品更关注响度而不是峰值，可以把算法改成 RMS：

```text
rms = sqrt(sum(sample[i]^2) / sampleCount)
```

## 三、写 WAV：`WavFileWriter.kt`

这个类只负责文件格式，不负责录音。它先写占位头，接收 16-bit PCM，关闭时回填文件大小。

```kotlin
package com.bigjelly.temporun.recorder

import java.io.Closeable
import java.io.File
import java.io.RandomAccessFile
import java.nio.ByteBuffer
import java.nio.ByteOrder

/**
 * 将 PCM 16-bit little-endian 数据写成标准 WAV 文件。
 *
 * 使用方式：
 * 1. 创建对象，构造函数会写入 44 字节占位头；
 * 2. 重复调用 writePcm16；
 * 3. 录音停止后调用 closeAndFinalize() 回填 WAV 头并关闭文件。
 */
class WavFileWriter(
    private val file: File,
    private val sampleRate: Int,
    private val channelCount: Int,
    private val bitsPerSample: Int = 16
) : Closeable {

    companion object {
        private const val HEADER_SIZE = 44
    }

    private val randomAccessFile: RandomAccessFile
    private var dataSize: Long = 0L
    private var closed = false

    init {
        require(sampleRate > 0) { "sampleRate must be greater than zero" }
        require(channelCount > 0) { "channelCount must be greater than zero" }
        require(bitsPerSample == 16) { "This implementation only supports PCM 16-bit" }

        file.parentFile?.mkdirs()
        randomAccessFile = RandomAccessFile(file, "rw")
        randomAccessFile.setLength(0L)

        // 先留下 WAV 头的位置，停止时再回填真实长度。
        randomAccessFile.write(ByteArray(HEADER_SIZE))
    }

    @Synchronized
    fun writePcm16(samples: ShortArray, offset: Int = 0, length: Int = samples.size) {
        check(!closed) { "WAV writer has already been closed" }
        require(offset >= 0 && length >= 0 && offset + length <= samples.size) {
            "Invalid samples range"
        }

        val bytes = ByteBuffer
            .allocate(length * 2)
            .order(ByteOrder.LITTLE_ENDIAN)

        for (index in offset until offset + length) {
            bytes.putShort(samples[index])
        }

        randomAccessFile.write(bytes.array())
        dataSize += length * 2L
    }

    /** 回填 RIFF/WAVE 头并关闭文件。重复调用也是安全的。 */
    @Synchronized
    fun closeAndFinalize() {
        if (closed) return

        // 经典 WAV 使用 32-bit 无符号长度字段，单个文件不能超过约 4 GiB。
        require(dataSize <= 0xffffffffL) { "WAV file is larger than 4 GiB" }

        val bytesPerSample = bitsPerSample / 8
        val blockAlign = channelCount * bytesPerSample
        val byteRate = sampleRate * blockAlign

        randomAccessFile.seek(0L)
        writeAscii("RIFF")
        writeUInt32LittleEndian(36L + dataSize)
        writeAscii("WAVE")

        writeAscii("fmt ")
        writeUInt32LittleEndian(16L) // PCM fmt 块大小
        writeUInt16LittleEndian(1) // 1 = PCM，无压缩
        writeUInt16LittleEndian(channelCount)
        writeUInt32LittleEndian(sampleRate.toLong())
        writeUInt32LittleEndian(byteRate.toLong())
        writeUInt16LittleEndian(blockAlign)
        writeUInt16LittleEndian(bitsPerSample)

        writeAscii("data")
        writeUInt32LittleEndian(dataSize)

        randomAccessFile.setLength(HEADER_SIZE + dataSize)
        randomAccessFile.close()
        closed = true
    }

    override fun close() {
        closeAndFinalize()
    }

    private fun writeAscii(value: String) {
        randomAccessFile.write(value.toByteArray(Charsets.US_ASCII))
    }

    private fun writeUInt16LittleEndian(value: Int) {
        randomAccessFile.write(value and 0xff)
        randomAccessFile.write((value ushr 8) and 0xff)
    }

    private fun writeUInt32LittleEndian(value: Long) {
        randomAccessFile.write((value and 0xff).toInt())
        randomAccessFile.write(((value ushr 8) and 0xff).toInt())
        randomAccessFile.write(((value ushr 16) and 0xff).toInt())
        randomAccessFile.write(((value ushr 24) and 0xff).toInt())
    }
}
```

注意：WAV 的多字节字段必须使用 little-endian。`ByteBuffer.order(ByteOrder.LITTLE_ENDIAN)` 只影响 PCM 样本写入；文件头的整数由 `writeUInt16LittleEndian` 和 `writeUInt32LittleEndian` 手动写入。

## 四、录音：`PcmRecorder.kt`

该类使用 `AudioRecord` 采集麦克风 PCM。录音线程每次读取约 20 ms 的数据，同时完成两件事：

- 写到 `WavFileWriter`；
- 计算当前块的峰值并回调给波形 View。

```kotlin
package com.bigjelly.temporun.recorder

import android.media.AudioFormat
import android.media.AudioRecord
import android.media.MediaRecorder
import java.io.File
import java.util.concurrent.atomic.AtomicBoolean
import kotlin.math.abs

/**
 * 使用 AudioRecord 录制 PCM 16-bit，并将数据保存为 WAV。
 *
 * 回调默认发生在录音线程，不要在回调中直接修改 View；调用方应切回主线程。
 */
class PcmRecorder {

    data class Config(
        val sampleRate: Int = 44_100,
        val channelMask: Int = AudioFormat.CHANNEL_IN_MONO,
        val channelCount: Int = 1,
        val bitsPerSample: Int = 16
    ) {
        init {
            require(sampleRate > 0)
            require(channelCount == 1) { "The sample code records mono audio" }
            require(bitsPerSample == 16) { "The sample code records PCM 16-bit" }
        }
    }

    enum class State {
        IDLE,
        RECORDING,
        STOPPING
    }

    @Volatile
    var state: State = State.IDLE
        private set

    var onAmplitude: ((Float) -> Unit)? = null
    var onStateChanged: ((State) -> Unit)? = null
    var onStopped: ((File) -> Unit)? = null
    var onError: ((Throwable) -> Unit)? = null

    private val stateLock = Any()
    private val stopRequested = AtomicBoolean(false)

    @Volatile
    private var audioRecord: AudioRecord? = null

    private var recordingThread: Thread? = null

    /**
     * 开始录音。成功返回 true；已经在录音或初始化失败时返回 false。
     */
    fun start(outputFile: File, config: Config = Config()): Boolean {
        synchronized(stateLock) {
            if (state != State.IDLE) return false

            val minBufferSize = AudioRecord.getMinBufferSize(
                config.sampleRate,
                config.channelMask,
                AudioFormat.ENCODING_PCM_16BIT
            )

            if (minBufferSize <= 0) {
                onError?.invoke(IllegalStateException("AudioRecord.getMinBufferSize failed"))
                return false
            }

            // 录音线程每次读取约 20 ms；AudioRecord 内部缓冲区至少取系统建议值的两倍。
            val samplesPerRead = (config.sampleRate / 50) * config.channelCount
            val requestedBytes = samplesPerRead * 2
            val audioBufferSize = maxOf(minBufferSize, requestedBytes * 2)

            var record: AudioRecord? = null
            var writer: WavFileWriter? = null

            try {
                outputFile.parentFile?.mkdirs()
                writer = WavFileWriter(
                    file = outputFile,
                    sampleRate = config.sampleRate,
                    channelCount = config.channelCount,
                    bitsPerSample = config.bitsPerSample
                )

                record = AudioRecord.Builder()
                    .setAudioSource(MediaRecorder.AudioSource.MIC)
                    .setAudioFormat(
                        AudioFormat.Builder()
                            .setEncoding(AudioFormat.ENCODING_PCM_16BIT)
                            .setSampleRate(config.sampleRate)
                            .setChannelMask(config.channelMask)
                            .build()
                    )
                    .setBufferSizeInBytes(audioBufferSize)
                    .build()

                val readyRecord = requireNotNull(record)
                val readyWriter = requireNotNull(writer)

                check(readyRecord.state == AudioRecord.STATE_INITIALIZED) {
                    "AudioRecord initialization failed"
                }

                stopRequested.set(false)
                readyRecord.startRecording()
                check(readyRecord.recordingState == AudioRecord.RECORDSTATE_RECORDING) {
                    "AudioRecord did not enter recording state"
                }

                audioRecord = readyRecord
                state = State.RECORDING
                onStateChanged?.invoke(State.RECORDING)

                val thread = Thread(
                    {
                        recordLoop(
                            record = readyRecord,
                            writer = readyWriter,
                            outputFile = outputFile,
                            samplesPerRead = samplesPerRead
                        )
                    },
                    "pcm-recorder"
                )
                recordingThread = thread
                thread.start()
                return true
            } catch (error: Throwable) {
                try {
                    record?.release()
                } catch (_: Throwable) {
                }
                try {
                    writer?.closeAndFinalize()
                } catch (_: Throwable) {
                }
                onError?.invoke(error)
                return false
            }
        }
    }

    /**
     * 请求停止。AudioRecord.stop() 会解除阻塞中的 read()，真正的文件关闭和 WAV 头回填
     * 在录音线程 finally 中完成，完成后才会收到 onStopped。
     */
    fun stop() {
        synchronized(stateLock) {
            if (state != State.RECORDING) return

            state = State.STOPPING
            stopRequested.set(true)
            onStateChanged?.invoke(State.STOPPING)

            try {
                audioRecord?.stop()
            } catch (error: IllegalStateException) {
                // 录音线程仍会继续执行 finally，负责释放资源和关闭文件。
                onError?.invoke(error)
            }
        }
    }

    private fun recordLoop(
        record: AudioRecord,
        writer: WavFileWriter,
        outputFile: File,
        samplesPerRead: Int
    ) {
        val buffer = ShortArray(samplesPerRead.coerceAtLeast(1))
        var recordingError: Throwable? = null

        try {
            while (!stopRequested.get()) {
                val readCount = record.read(
                    buffer,
                    0,
                    buffer.size,
                    AudioRecord.READ_BLOCKING
                )

                when {
                    readCount > 0 -> {
                        writer.writePcm16(buffer, 0, readCount)
                        onAmplitude?.invoke(calculatePeak(buffer, readCount))
                    }

                    readCount == AudioRecord.ERROR_INVALID_OPERATION -> {
                        error("AudioRecord returned ERROR_INVALID_OPERATION")
                    }

                    readCount == AudioRecord.ERROR_BAD_VALUE -> {
                        error("AudioRecord returned ERROR_BAD_VALUE")
                    }

                    readCount == AudioRecord.ERROR_DEAD_OBJECT -> {
                        error("AudioRecord returned ERROR_DEAD_OBJECT")
                    }

                    else -> {
                        error("AudioRecord.read failed: $readCount")
                    }
                }
            }
        } catch (error: Throwable) {
            // 用户主动 stop() 时，部分设备可能从 read() 返回异常；这种情况不覆盖正常停止。
            if (!stopRequested.get()) recordingError = error
        } finally {
            try {
                if (record.recordingState == AudioRecord.RECORDSTATE_RECORDING) {
                    record.stop()
                }
            } catch (_: Throwable) {
            }

            try {
                record.release()
            } catch (_: Throwable) {
            }
            audioRecord = null

            try {
                writer.closeAndFinalize()
            } catch (error: Throwable) {
                if (recordingError == null) recordingError = error
            }

            state = State.IDLE
            recordingThread = null

            recordingError?.let { onError?.invoke(it) }
            onStateChanged?.invoke(State.IDLE)
            onStopped?.invoke(outputFile)
        }
    }

    private fun calculatePeak(samples: ShortArray, count: Int): Float {
        var maxAbs = 0
        for (index in 0 until count) {
            maxAbs = maxOf(maxAbs, abs(samples[index].toInt()))
        }
        return (maxAbs / 32768f).coerceIn(0f, 1f)
    }
}
```

### 录音类的几个关键点

1. `AudioRecord.getMinBufferSize()` 返回负数时不能继续创建录音器。
2. `AudioRecord.read()` 返回负数是错误，不应把它当作 PCM 数据写入文件。
3. `stop()` 只发出停止请求；`onStopped` 代表 WAV 已经完成回填，可以安全播放。
4. 回调来自录音线程，UI 层必须使用 `runOnUiThread` 或 `Handler(Looper.getMainLooper())`。
5. 录音线程只传递一个 `Float` 振幅值，不把整个 PCM 缓冲区交给 UI，避免大量对象和线程切换。

## 五、自定义波形 View：`WaveformView.kt`

这个 View 保存最近一段振幅值，使用 `Canvas` 和 `Path` 画出相对于中线对称的填充包络。最多保留 600 个点，避免录音时间很长时内存无限增长。

```kotlin
package com.bigjelly.temporun.recorder

import android.content.Context
import android.graphics.Canvas
import android.graphics.Color
import android.graphics.Paint
import android.graphics.Path
import android.util.AttributeSet
import android.view.View
import android.os.Looper

class WaveformView @JvmOverloads constructor(
    context: Context,
    attrs: AttributeSet? = null
) : View(context, attrs) {

    private val amplitudes = ArrayList<Float>(600)
    private val maxPointCount = 600

    private val fillPaint = Paint(Paint.ANTI_ALIAS_FLAG).apply {
        style = Paint.Style.FILL
        color = Color.rgb(55, 178, 255)
    }

    private val baselinePaint = Paint(Paint.ANTI_ALIAS_FLAG).apply {
        style = Paint.Style.STROKE
        strokeWidth = resources.displayMetrics.density
        color = Color.rgb(90, 100, 110)
    }

    /** 必须在主线程调用；如果从录音线程调用，会自动 post 到主线程。 */
    fun addAmplitude(amplitude: Float) {
        if (Looper.myLooper() != Looper.getMainLooper()) {
            post { addAmplitude(amplitude) }
            return
        }

        amplitudes.add(amplitude.coerceIn(0f, 1f))
        if (amplitudes.size > maxPointCount) {
            amplitudes.removeAt(0)
        }
        invalidate()
    }

    fun clearWaveform() {
        if (Looper.myLooper() != Looper.getMainLooper()) {
            post { clearWaveform() }
            return
        }
        amplitudes.clear()
        invalidate()
    }

    override fun onDraw(canvas: Canvas) {
        super.onDraw(canvas)

        val width = width.toFloat()
        val height = height.toFloat()
        val centerY = height / 2f

        canvas.drawColor(Color.rgb(18, 22, 27))
        canvas.drawLine(0f, centerY, width, centerY, baselinePaint)

        if (amplitudes.isEmpty() || width <= 0f || height <= 0f) return

        val path = Path()
        val lastIndex = amplitudes.lastIndex
        val xStep = if (lastIndex == 0) 0f else width / lastIndex

        // 先从左到右画上包络。
        for (index in amplitudes.indices) {
            val x = if (lastIndex == 0) width / 2f else index * xStep
            val halfHeight = amplitudes[index] * height * 0.45f
            val y = centerY - halfHeight

            if (index == 0) path.moveTo(x, y) else path.lineTo(x, y)
        }

        // 再从右到左画下包络，闭合后填充成上下对称的波形。
        for (index in lastIndex downTo 0) {
            val x = if (lastIndex == 0) width / 2f else index * xStep
            val halfHeight = amplitudes[index] * height * 0.45f
            path.lineTo(x, centerY + halfHeight)
        }
        path.close()

        canvas.drawPath(path, fillPaint)
    }
}
```

这里画的是“振幅包络”，而不是把每一个 16-bit 采样点都画出来。直接绘制每个采样点会产生数万甚至数百万个点，既没有必要，也会让 View 绘制压力过大。录音线程已经把一小段 PCM 压缩成了一个峰值，View 只需要画这些峰值。

## 六、播放 WAV：`WavPcmPlayer.kt`

为了完整体现“录到的 PCM 如何播放”，这里直接用 `AudioTrack` 播放 WAV 中的 `data` 块。该实现读取 `fmt ` 和 `data` chunk，不假设 WAV 头一定是固定 44 字节，因此对带有额外块的普通 WAV 更稳健。

```kotlin
package com.bigjelly.temporun.recorder

import android.media.AudioAttributes
import android.media.AudioFormat
import android.media.AudioTrack
import java.io.File
import java.io.RandomAccessFile
import java.util.concurrent.atomic.AtomicLong

class WavPcmPlayer {

    private data class WavHeader(
        val sampleRate: Int,
        val channelCount: Int,
        val bitsPerSample: Int,
        val dataOffset: Long,
        val dataSize: Long
    )

    private val generation = AtomicLong(0L)

    @Volatile
    private var audioTrack: AudioTrack? = null

    /** 返回 false 表示文件不存在；播放过程中的错误通过 onError 回调。 */
    fun play(
        file: File,
        onFinished: () -> Unit = {},
        onError: (Throwable) -> Unit = {}
    ): Boolean {
        if (!file.isFile) return false

        stop()
        val sessionId = generation.incrementAndGet()

        Thread(
            {
                playInternal(file, sessionId, onFinished, onError)
            },
            "wav-pcm-player"
        ).start()

        return true
    }

    fun stop() {
        generation.incrementAndGet()
        try {
            audioTrack?.stop()
        } catch (_: Throwable) {
        }
    }

    private fun playInternal(
        file: File,
        sessionId: Long,
        onFinished: () -> Unit,
        onError: (Throwable) -> Unit
    ) {
        var track: AudioTrack? = null
        try {
            RandomAccessFile(file, "r").use { input ->
                val header = readWavHeader(input)
                require(header.bitsPerSample == 16) {
                    "Only PCM 16-bit WAV is supported"
                }
                require(header.channelCount == 1 || header.channelCount == 2) {
                    "Only mono and stereo WAV are supported"
                }

                val outputChannelMask = if (header.channelCount == 1) {
                    AudioFormat.CHANNEL_OUT_MONO
                } else {
                    AudioFormat.CHANNEL_OUT_STEREO
                }

                val minBufferSize = AudioTrack.getMinBufferSize(
                    header.sampleRate,
                    outputChannelMask,
                    AudioFormat.ENCODING_PCM_16BIT
                )
                require(minBufferSize > 0) { "AudioTrack.getMinBufferSize failed" }

                track = AudioTrack.Builder()
                    .setAudioAttributes(
                        AudioAttributes.Builder()
                            .setUsage(AudioAttributes.USAGE_MEDIA)
                            .setContentType(AudioAttributes.CONTENT_TYPE_MUSIC)
                            .build()
                    )
                    .setAudioFormat(
                        AudioFormat.Builder()
                            .setEncoding(AudioFormat.ENCODING_PCM_16BIT)
                            .setSampleRate(header.sampleRate)
                            .setChannelMask(outputChannelMask)
                            .build()
                    )
                    .setBufferSizeInBytes(maxOf(minBufferSize, 4096))
                    .build()

                check(track.state == AudioTrack.STATE_INITIALIZED) {
                    "AudioTrack initialization failed"
                }

                if (generation.get() != sessionId) return

                audioTrack = track
                track.play()
                input.seek(header.dataOffset)

                val buffer = ByteArray(maxOf(4096, minBufferSize))
                var remaining = header.dataSize

                while (remaining > 0L && generation.get() == sessionId) {
                    val requestSize = minOf(buffer.size.toLong(), remaining).toInt()
                    val readCount = input.read(buffer, 0, requestSize)
                    if (readCount <= 0) break

                    val written = track.write(buffer, 0, readCount)
                    check(written > 0) { "AudioTrack.write failed: $written" }
                    remaining -= written.toLong()
                }

                if (track.playState == AudioTrack.PLAYSTATE_PLAYING) {
                    track.stop()
                }

                if (remaining == 0L && generation.get() == sessionId) {
                    onFinished()
                }
            }
        } catch (error: Throwable) {
            if (generation.get() == sessionId) onError(error)
        } finally {
            try {
                track?.release()
            } catch (_: Throwable) {
            }
            if (audioTrack === track) audioTrack = null
        }
    }

    private fun readWavHeader(input: RandomAccessFile): WavHeader {
        require(readFourCc(input) == "RIFF") { "Not a RIFF file" }
        readUInt32LittleEndian(input) // RIFF 文件大小，当前只用于移动指针
        require(readFourCc(input) == "WAVE") { "Not a WAVE file" }

        var audioFormat = -1
        var channelCount = -1
        var sampleRate = -1
        var bitsPerSample = -1
        var dataOffset = -1L
        var dataSize = -1L

        while (input.filePointer + 8L <= input.length()) {
            val chunkId = readFourCc(input)
            val chunkSize = readUInt32LittleEndian(input)
            val chunkDataStart = input.filePointer
            require(chunkDataStart + chunkSize <= input.length()) {
                "WAV chunk exceeds file length"
            }

            when (chunkId) {
                "fmt " -> {
                    require(chunkSize >= 16L) { "Invalid fmt chunk" }
                    audioFormat = readUInt16LittleEndian(input)
                    channelCount = readUInt16LittleEndian(input)
                    sampleRate = readUInt32LittleEndian(input).toInt()
                    input.skipBytes(6) // byteRate 4 + blockAlign 2
                    bitsPerSample = readUInt16LittleEndian(input)
                }

                "data" -> {
                    dataOffset = chunkDataStart
                    dataSize = chunkSize
                    break
                }
            }

            input.seek(chunkDataStart + chunkSize + (chunkSize and 1L))
        }

        require(audioFormat == 1) { "Only uncompressed PCM WAV is supported" }
        require(channelCount > 0 && sampleRate > 0 && bitsPerSample > 0) {
            "WAV fmt chunk is missing or invalid"
        }
        require(dataOffset >= 0L && dataSize >= 0L) { "WAV data chunk is missing" }

        return WavHeader(
            sampleRate = sampleRate,
            channelCount = channelCount,
            bitsPerSample = bitsPerSample,
            dataOffset = dataOffset,
            dataSize = dataSize
        )
    }

    private fun readFourCc(input: RandomAccessFile): String {
        val bytes = ByteArray(4)
        input.readFully(bytes)
        return String(bytes, Charsets.US_ASCII)
    }

    private fun readUInt16LittleEndian(input: RandomAccessFile): Int {
        val low = input.readUnsignedByte()
        val high = input.readUnsignedByte()
        return low or (high shl 8)
    }

    private fun readUInt32LittleEndian(input: RandomAccessFile): Long {
        val b0 = input.readUnsignedByte().toLong()
        val b1 = input.readUnsignedByte().toLong()
        val b2 = input.readUnsignedByte().toLong()
        val b3 = input.readUnsignedByte().toLong()
        return b0 or (b1 shl 8) or (b2 shl 16) or (b3 shl 24)
    }
}
```

`WavPcmPlayer` 使用一个递增的 `generation` 区分播放会话。开始新播放或调用 `stop()` 后，旧线程即使稍后从 `AudioTrack.write()` 返回，也不会再触发新的完成回调。

## 八、页面控制器：`RecorderActivity.kt`

这个 Activity 负责权限、按钮、线程回调和文件路径。录音文件放在应用内部目录：

```text
/data/user/0/com.bigjelly.temporun/files/recordings/record_时间戳.wav
```

该位置不需要存储权限，应用卸载时会一起删除；如果后续需要让其他应用或用户看到文件，再考虑 MediaStore 或 SAF。

```kotlin
package com.bigjelly.temporun.recorder

import android.Manifest
import android.app.Activity
import android.content.pm.PackageManager
import android.os.Bundle
import android.widget.Button
import android.widget.TextView
import java.io.File

class RecorderActivity : Activity() {

    companion object {
        private const val REQUEST_RECORD_AUDIO = 1001
    }

    private val recorder = PcmRecorder()
    private val player = WavPcmPlayer()

    private lateinit var statusText: TextView
    private lateinit var waveformView: WaveformView
    private var lastRecordedFile: File? = null

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_recorder)

        statusText = findViewById(R.id.tv_record_status)
        waveformView = findViewById(R.id.waveform_view)
        val startButton = findViewById<Button>(R.id.btn_start_record)
        val stopButton = findViewById<Button>(R.id.btn_stop_record)
        val playButton = findViewById<Button>(R.id.btn_play_record)

        recorder.onAmplitude = { amplitude ->
            // onAmplitude 来自录音线程，WaveformView 会自动切回主线程。
            waveformView.addAmplitude(amplitude)
        }

        recorder.onStateChanged = { state ->
            runOnUiThread {
                statusText.text = when (state) {
                    PcmRecorder.State.IDLE -> "空闲"
                    PcmRecorder.State.RECORDING -> "正在录音…"
                    PcmRecorder.State.STOPPING -> "正在保存 WAV…"
                }
            }
        }

        recorder.onStopped = { file ->
            runOnUiThread {
                lastRecordedFile = file
                statusText.text = "录音已保存：${file.name}"
            }
        }

        recorder.onError = { error ->
            runOnUiThread {
                statusText.text = "错误：${error.message ?: error.javaClass.simpleName}"
            }
        }

        startButton.setOnClickListener {
            startOrRequestPermission()
        }

        stopButton.setOnClickListener {
            recorder.stop()
        }

        playButton.setOnClickListener {
            val file = lastRecordedFile
            if (file == null || !file.isFile) {
                statusText.text = "还没有可播放的录音"
                return@setOnClickListener
            }

            statusText.text = "正在播放：${file.name}"
            val accepted = player.play(
                file = file,
                onFinished = {
                    runOnUiThread { statusText.text = "播放完成" }
                },
                onError = { error ->
                    runOnUiThread {
                        statusText.text =
                            "播放失败：${error.message ?: error.javaClass.simpleName}"
                    }
                }
            )
            if (!accepted) statusText.text = "录音文件不存在"
        }
    }

    private fun startOrRequestPermission() {
        if (android.os.Build.VERSION.SDK_INT >= android.os.Build.VERSION_CODES.M &&
            checkSelfPermission(Manifest.permission.RECORD_AUDIO) !=
            PackageManager.PERMISSION_GRANTED
        ) {
            requestPermissions(
                arrayOf(Manifest.permission.RECORD_AUDIO),
                REQUEST_RECORD_AUDIO
            )
            return
        }

        startRecording()
    }

    private fun startRecording() {
        val outputDirectory = File(filesDir, "recordings")
        val outputFile = File(
            outputDirectory,
            "record_${System.currentTimeMillis()}.wav"
        )

        waveformView.clearWaveform()
        lastRecordedFile = null
        statusText.text = "正在初始化录音…"

        if (!recorder.start(outputFile)) {
            statusText.text = "录音启动失败"
        }
    }

    override fun onRequestPermissionsResult(
        requestCode: Int,
        permissions: Array<out String>,
        grantResults: IntArray
    ) {
        super.onRequestPermissionsResult(requestCode, permissions, grantResults)

        if (requestCode == REQUEST_RECORD_AUDIO) {
            if (grantResults.firstOrNull() == PackageManager.PERMISSION_GRANTED) {
                startRecording()
            } else {
                statusText.text = "没有录音权限，无法使用麦克风"
            }
        }
    }

    override fun onDestroy() {
        recorder.stop()
        player.stop()
        super.onDestroy()
    }
}
```

这里采用 `Activity` 原生权限 API，不需要新增依赖。项目已经使用了 AndroidX，但这套代码不依赖 `ContextCompat` 或 Activity Result API，因此和当前工程的依赖配置更直接匹配。

## 十一、完整运行流程

### 1. 点击“开始录音”

1. 检查 `RECORD_AUDIO` 运行时权限；
2. 第一次没有权限时弹出系统授权框；
3. 创建内部目录 `files/recordings`；
4. 创建以时间戳命名的 WAV 文件；
5. 写入 44 字节占位头；
6. 创建 `AudioRecord`；
7. 在录音线程中不断读取 PCM。

### 2. 录音进行中

每次 `read()` 成功后：

```text
ShortArray
  ├─→ WavFileWriter.writePcm16()
  └─→ calculatePeak()
          └─→ WaveformView.addAmplitude()
```

波形 View 每次只接收一个 `Float`，而不是接收完整 PCM。View 通过 `invalidate()` 请求重绘，在 `onDraw()` 中重新构造包络 Path。

### 3. 点击“停止录音”

1. 设置 `stopRequested = true`；
2. 调用 `AudioRecord.stop()`，解除阻塞的 `read()`；
3. 录音线程退出循环；
4. 释放 `AudioRecord`；
5. 根据 PCM 字节数回填 WAV 头；
6. 关闭文件；
7. 回调 `onStopped`；
8. 此时才允许点击“播放录音”。

### 4. 点击“播放录音”

1. 解析 WAV 的 `fmt ` 和 `data` 块；
2. 读取采样率、声道数、位深；
3. 用相同参数创建 `AudioTrack`；
4. 从 `data` 块开始分块读取 PCM；
5. 通过 `AudioTrack.write()` 送到音频输出。

## 十二、测试与验证

建议按下面顺序验证：

### 权限

- 第一次点击开始录音能出现系统权限框；
- 拒绝权限后页面显示错误，不崩溃；
- 在系统设置中重新授权后可以录音；
- Android 模拟器如果没有配置虚拟麦克风，波形可能一直接近 0，这是环境问题，不一定是代码问题。

### 文件

录音停止后，至少检查：

- 文件存在；
- 文件大小大于 44 字节；
- 文件前 4 字节是 `RIFF`；
- 第 9～12 字节是 `WAVE`；
- `data` 块长度等于文件实际 PCM 长度；
- 重新进入页面后旧文件仍在应用内部目录中。

### 音频

- 说话时波形高度变化，安静时趋近中线；
- 录音停止后播放声音正常；
- 连续录制两次，第二次不会把第一次文件覆盖；
- 播放过程中点击播放新文件，旧播放不会继续回调“播放完成”；
- 录音过程中销毁 Activity，线程最终能释放资源。

## 十三、常见问题与工程化建议

### 1. 不要在 `onDraw()` 中读取麦克风

`onDraw()` 只负责根据已有振幅数据绘图。录音、文件写入和振幅计算都应发生在工作线程。

### 2. 不要每个采样点都刷新 UI

44.1 kHz 意味着每秒 44,100 个采样点。如果每个点都 `invalidate()`，UI 线程会被淹没。本方案按音频块聚合，通常每秒回调几十次，已经足够平滑。

### 3. 录音停止必须完成 WAV 头回填

不能只调用 `AudioRecord.stop()` 就认为文件完成。只有 `WavFileWriter.closeAndFinalize()` 返回后，文件才是完整 WAV。

### 4. 录音期间不要把文件放在公共存储根目录

本方案使用 `filesDir`，不需要申请存储权限，也不会遇到 Android 10 以后分区存储的路径问题。若产品要求导出文件，应使用 `MediaStore` 或系统文件选择器，并在录音完成之后复制或发布文件。

### 5. 如果需要后台录音

当前示例是页面内录音，Activity 销毁时停止录音。后台或锁屏继续录音需要进一步改造：

- 将录音逻辑放入前台 Service；
- 声明并申请 `FOREGROUND_SERVICE_MICROPHONE`（按目标 SDK 的要求配置）；
- 显示持续通知；
- 正确处理麦克风占用、电话、蓝牙和音频焦点；
- 不让 Service 直接持有 Activity 或 View。

### 6. 如果要支持暂停/继续

暂停时可以调用 `AudioRecord.stop()`，但不能关闭 WAV；继续时重新创建或重新启动录音器，继续向同一个 `WavFileWriter` 追加 PCM。实际实现要明确处理采样时间是否允许出现空白，以及不同录音段参数是否一致。

### 7. 如果需要保存完整历史波形

当前 View 只保留最近 600 个振幅点，适合实时预览。要画完整录音波形，可以在录音时把每个块的峰值另存为一个小型 envelope 文件，播放或打开详情页时再按 View 宽度降采样，而不是重新加载全部 PCM。

## 十四、方案小结

这套实现将职责拆成四层：

| 层 | 类 | 职责 |
|---|---|---|
| 采集层 | `PcmRecorder` | 从麦克风读取 PCM、计算振幅、管理录音线程 |
| 文件层 | `WavFileWriter` | 写 PCM、生成并回填 WAV 头 |
| 播放层 | `WavPcmPlayer` | 解析 WAV、用 AudioTrack 播放 PCM |
| UI 层 | `WaveformView`、`RecorderActivity` | 绘制波形、权限、按钮和状态 |

先按本文新增文件并注册 `RecorderActivity`，即可在当前项目中验证“录音 PCM → 写入 WAV → 播放”和实时振幅包络。验证通过后，再根据产品需求把录音页面合并进现有 `MainActivity`，或将 `PcmRecorder` 提升为 ViewModel/前台 Service 所持有的业务组件。
